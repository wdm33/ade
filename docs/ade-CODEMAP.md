## Conventions

- A **module** in Ade is a Cargo workspace crate (the smallest independently-buildable unit). Source: `Cargo.toml` `[workspace] members` (**12** entries). One exception to crate-granularity: `ade_network` is split by *submodule color* — `.idd-config.json` `core_paths` resolves BLUE at the submodule-path level (9 paths), so its BLUE / RED submodules are documented as separate entries.

### TCB color sources (in order of authority)

1. `.idd-config.json` `core_paths` — substring match against the module's absolute path ⇒ BLUE (6 BLUE crates: `ade_codec`, `ade_types`, `ade_crypto`, `ade_core`, `ade_plutus`, `ade_ledger`; plus 9 BLUE `ade_network` submodule paths).
2. `CLAUDE.md` role notes (`ade_runtime` = RED shell; `ade_testkit` = GREEN test infra; `ade_node` = the binary; `ade_mem_diag` = RED unsafe quarantine).
3. Module banner signals — the `// Core Contract:` / `//! BLUE …` / `//! GREEN …` / `//! RED …` headers at the top of each source file, plus the BLUE `lib.rs` deny attributes.
4. Import heuristic — a module reaching for tokio / sockets / files / clock / rand is RED; a deterministic glue module over BLUE is GREEN.

## BLUE Modules — Pure Functional Core

> **Shared header (applies to every BLUE entry below).** Every `.rs` source file begins with the `// Core Contract:` banner ("Deterministic: same inputs ⇒ byte-identical outputs; no wall-clock / true-randomness / HashMap/HashSet / float; encode invariants in types; explicit state transitions only; canonical serialization for all persisted/hashed data"), and each crate's `lib.rs` (or, for `ade_network`, the crate root — BLUE submodules inherit it) carries the deny attributes: `#![deny(unsafe_code)]`, `#![deny(clippy::unwrap_used)]`, `#![deny(clippy::expect_used)]`, `#![deny(clippy::panic)]`, `#![deny(clippy::float_arithmetic)]`.
>
> **The `#![deny(unsafe_code)]` invariant holds.** The one workspace `unsafe` (mimalloc `mi_collect`) stays quarantined in the dedicated RED crate `ade_mem_diag`, the SOLE crate without `#![deny(unsafe_code)]`. `ade_node` keeps `#![deny(unsafe_code)]` with zero local allows.
>
> **The new self-sustaining-ledger BLUE core is pure.** The `EpochAccumulator` transition (`apply_selected_block`), the `FrozenLeadershipPoolDistr` leadership authority, the `ReducedBoundaryProjection`, the `admit_rollback` recovery rail, the Conway ratification/enactment authority, and the value/param types all use `BTreeMap`/`Vec` only (no `HashMap`), checked arithmetic + fail-closed overflow (no float), and canonical fixed-width byte encodings with round-trip + tamper-evidence tests. The boundary work **reuses** the byte-exact-verified single authorities (`rules::apply_epoch_boundary_with_registrations`, `process_block_certificates`, `epoch::rotate_snapshots`) — it does not reimplement them.
>
> Cross-cutting BLUE CI gates (scope the full BLUE set — 6 BLUE crates + 9 BLUE `ade_network` submodule paths): `ci_check_module_headers.sh`, `ci_check_forbidden_patterns.sh`, `ci_check_dependency_boundary.sh`, `ci_check_no_signing_in_blue.sh`, `ci_check_no_semantic_cfg.sh`, `ci_check_hash_uses_wire_bytes.sh`, `ci_check_ingress_chokepoints.sh`, `ci_check_pallas_quarantine.sh`, `ci_check_no_async_in_blue.sh`.
