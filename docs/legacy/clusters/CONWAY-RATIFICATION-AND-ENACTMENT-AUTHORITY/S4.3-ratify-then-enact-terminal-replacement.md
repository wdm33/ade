Option Y (one unified authority), implemented as a **single-authority extraction** — NOT an in-place patch to the
existing incomplete enactment branch. Option X (enactment in the accumulator while the shared boundary keeps its partial

## The authority cut — one planner, one application point

Create ONE pure BLUE authority:

```
plan_conway_governance_epoch(input) -> Result<ConwayGovernanceEpochPlan, GovernanceTerminal>
```

Only the boundary transition APPLIES its output. The accumulator may PROVIDE inputs and PERSIST results, but it must NOT
separately decide proposal removal, refund, enactment, pparam mutation, or predecessor-root updates.

`ConwayGovernanceEpochPlan` is ONE complete delta:
- next governance proposal forest/map
- removals: `GovActionId -> RemovalCause` (`Enacted | PrunedByEnactment | Expired`)
- reward-account credits (registered return addresses)
- unclaimed deposits → treasury credits (deregistered return addresses)
- next protocol parameters
- next previous-action roots
- committee / constitution / treasury deltas where supported

`apply_gov_deposit_refunds` and the old `enact_proposals` boundary logic must be DELETED or become THIN CALLERS of this
same planner. **No partial old enactment path may remain reachable** (today: `apply_gov_deposit_refunds` at
`epoch_accumulator.rs:575` + the incomplete enact block at `rules.rs:1283-1340`, which drops params — `protocol_params`
cloned at `:1406` — and only logs `deposits_returned`).
