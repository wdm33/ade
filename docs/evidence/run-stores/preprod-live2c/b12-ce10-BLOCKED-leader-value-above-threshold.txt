## THREE CORRECTIONS TO THE RECORDED CHARACTERISATION

The blocker was recorded on 2026-08-16 as firing "during a long catch-up", with a ~0.005% margin,
and as something a warm restart could work around. All three are wrong.

**(1) It is NOT catch-up-length dependent.** It fired on the FIRST sync step of a warm restart,
before a single block was admitted, with the durable tip 582k slots behind the peer. The length of
the catch-up is irrelevant: the store is parked immediately before a header Ade rejects.

**(2) It is DETERMINISTIC, and the operands prove it.** Three occurrences, byte-identical `value`
AND `threshold`:

  2026-08-16  binary 56e0a4e4  durable tip ~130,733,645   (BND-2d leg 1)
  2026-08-29  binary 96c7af68  durable tip  130,739,648   (attempt 1)
  2026-08-29  binary 96c7af68  durable tip  130,739,648   (attempt 2)

Two binaries, thirteen days apart. A restart does NOT work around it — BND-2d's leg 2 got past
130,733,645 and simply stopped, by clean SIGINT, before re-reaching the wall.

**(3) The margin is 0.0315%, not ~0.005%.** Recomputed from the raw bytes:

  value      1,007,308,967,828,955    0x394246534dddb
  threshold  1,006,991,541,021,466    0x393da7d182b1a
  value − threshold  =  317,426,807,489
  value / threshold  =  1.000315223        →  0.031522 % over

## THE OPERAND THAT SHOULD OPEN THE NEXT SLICE

  bootstrap_epoch          304   (durable_epoch_start_slot=129686400, anchor_slot=129813427)
  durable tip 130,739,648  →  epoch 306      (window 130,550,400 .. 130,982,399)

  **The failing header is in epoch 306 = seed + 2.**

That is not a new region of the map. Seed+2 is where this project has repeatedly found stake- and
nonce-derivation residuals — the b3c seed+2 stake residual (Option B, `c4e0413b`), the seed+2 eta0
work, and the go-stake derivation delta. The header's leader threshold is a function of the pool's
sigma in the ACTIVE (`go`) stake snapshot for its epoch, and for epoch 306 that snapshot is the
state as of the END of epoch 304 — whereas this store was seeded from a certified Mithril anchor
at slot 129,813,427, which is *mid*-epoch-304.

A sigma that is slightly wrong yields a threshold that is slightly wrong, and 0.03% is exactly that
size. **Start there, and measure it rather than assume it** — the epoch is NOT stale (Ade's own
authority is on 306, the header's own epoch), so "the authority is an epoch behind" is already
refuted and should not be re-derived.

## A DIAGNOSTIC GAP THE NEXT SLICE HITS IMMEDIATELY

`LeaderValueAboveThreshold` carries `value` and `threshold` and NOTHING ELSE — no slot, no header
hash, no pool id. So the error cannot say WHICH header failed, and the operands it does carry are
the two derived numbers rather than the inputs that produced them. That is the same shape as the
BND-1 finding (one error variant for two causes) and the NONCE-1 finding (two hashes named, neither
of their operands): a rule that reports its conclusion but not its premises is un-diagnosable
without a bespoke probe. Widening this error is likely the first move, not an afterthought.
