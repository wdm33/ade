## WHAT WAS PROVEN, AND HOW

**CE-BND1-1 / CE-BND1-4** — `a_within_epoch_apply_failure_is_apply_failed_not_a_boundary`: a block in
the accumulator's own epoch whose apply fail-closes yields `ApplyFailed` carrying the ledger's typed
error, compared BY VALUE (`LedgerTransitionError::EraMismatch { .. }`), not by substring.

**CE-BND1-2** — `a_crossing_is_classified_from_the_epochs_even_when_the_apply_would_fail`: a block one
epoch ahead is `BoundaryMarkRequired { from, to }` even when its apply WOULD have failed. Under the old
error-derived classification that case was indistinguishable from an ordinary apply failure. This is
the test that pins the predicate as positive rather than inferred.

**CE-BND1-3** — the gate extracts the apply-failure arm and asserts it calls NONE of
`position_reduced_checkpoint_at_boundary`, `sum_base_credential_stake`,
`cross_accumulator_over_boundary_block`, `bind_boundary_mark`.

**CE-BND1-7 — both halves NEGATIVE-TESTED, not asserted:**
  * predicate `>` → `>=`: fails the new test AND 5 pre-existing ones (the comparison is load-bearing,
    not decorative).
  * `sum_base_credential_stake` put back into the apply-failure arm: the gate catches it.
  * The gate also asserts a NONZERO passing-test count, so it cannot pass vacuously (14 tests ran).

## A GATE-SCOPING CORRECTION WORTH RECORDING
The gate's first draft grepped the whole file for `Stalled` / `format!("{e:?}")` and failed on
`AccumulatorBoundaryOutcome::Stalled` — a DIFFERENT enum (the outcome of an actual cross attempt) that
this slice legitimately leaves alone. The checks are now scoped to the two enum bodies that were split
and to the advancer function. A gate that fails on correct code is not a stricter gate; it is a gate
that gets disabled.

## WHAT THIS DOES NOT DO — stated so the numbers are not misread
The cursor is STILL PINNED at 130,350,114 and the accumulator still cannot cross 130,350,133. BND-1
removed a wrong control-flow path; it did not touch the semantics that block progress. The 108 s figure
is a CONSEQUENCE of separating the two failure classes, not the reason for doing it — the slice would
have been worth landing at zero time saved, because a within-epoch failure masquerading as a boundary
failure is a correctness defect regardless of what it costs.

**BND-2 remains the authority blocker**, unchanged and deliberately untouched:
`tx0[invalid=true certs=false wdl=2 votes=false proposals=false collateral=None]` — the withdrawal
limb, and behind it the undeclared-collateral input gap. Its entry point is reference-semantics
extraction against cardano-ledger (which body effects a phase-2-invalid Conway tx discards, and how the
consumed collateral is determined when `total_collateral` is absent), NOT implementation. The
sufficiency contract to preserve while answering it: `EpochAccumulator + reduced UTxO authority +
canonical block` — the open question is how the accumulator obtains a DETERMINISTIC collateral delta
from the UTxO authority, never whether it should become a second UTxO owner.

`InvalidTxCarriesAuthorityEffect` is unchanged. B12 is unchanged.
