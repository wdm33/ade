## ROOT CAUSE — a positioning mismatch between two derived stores

`node_lifecycle.rs` advances the reduced checkpoint **to the durable tip** at the end of every
co-advance pass (`advance_reduced_checkpoint_forward_to(reduced_checkpoint, chaindb, tip.slot)`).
So while the accumulator walks at cursor ~130,350,114, the checkpoint is already at the tip
(~130,550,441). By then `0326ab20…#1` has been spent — **by this very block**, under BND-2a's now-
correct collateral consumption — so the UTxO authority genuinely no longer holds it and truthfully
answers `None`.

The two derived stores advance over the same chain at different rates, and the accumulator asks the
UTxO authority for a value at a point the authority has already moved past.

## A WRONG CLAIM I MADE EARLIER, CORRECTED HERE
When deferring CE-2b-7 in the BND-2b slice I wrote: *"during the accumulator's walk the reduced
checkpoint is positioned AT the block, so `0326ab20…#1` resolves"*. **That is false**, and it was
the stated reason for not proving the real-block value at BND-2b time. The live gate is what caught
it. The deferral was defensible on tool-proliferation grounds; the reasoning attached to it was not.

## WHAT THIS VINDICATES
Keeping `InvalidTxCollateralNeedsUtxo` / the typed unresolved-collateral refusal was right. Had the
guard been retired on the strength of green unit tests, the accumulator would have credited a wrong
value or silently skipped the contribution. Instead it refused, NAMED the exact unresolvable input,
left the cursor pinned, and did not halt the node (the follow continued — 85 `follow: tip` lines
after the refusal, so observe-only held).

It also exposes a real gap in the unit tests: every test resolver ANSWERS. `FixedResolver` always
returns a value, and `EmptyResolver` proves the refusal path — but nothing tested that the *live*
authority can answer *at walk time*. That was exactly CE-2c-1, and only the live venue could test it.

## THREE CANDIDATE FIXES — recorded, none chosen here
1. **Lockstep** — advance checkpoint and accumulator per block together. Architecturally honest;
   a significant co-advancer change.
2. **Resolve at first sight** — the checkpoint computes `collAdaBalance` while applying that block,
   when it still holds the entry, and carries the scalar forward. Matches "the UTxO authority
   resolves"; needs somewhere to carry a per-block derived fact.
3. **Position on demand** — rewind the checkpoint to the accumulator's cursor. This is the B6 thrash
   shape and should be argued against, not adopted by default.
