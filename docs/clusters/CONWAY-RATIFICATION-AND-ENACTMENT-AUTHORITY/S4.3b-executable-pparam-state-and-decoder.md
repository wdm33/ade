# S4.3b — V11 executable execution-memory + previous-action state (all INERT)

## The narrow question

S4.3a unified the boundary under one governance authority but does NO enactment. Before S4.3c can atomically enact
the exec-memory `ParameterChange` witness (69c948cd..#0), the authoritative state must REPRESENT the change and its
lineage. S4.3b adds that capacity as ONE V11 state migration — three fields that together are the sufficient-authority
set for S4.3c — all INERT (nothing consumes them yet). This is the S4.1 shape (add versioned `num_dormant` inert, before
S4.2 activated it): represent-not-activate. Governed by [[feedback_versioned_authoritative_state_no_fabricated_default]]
+ the `cluster.md` §5 seam (census-observable → live input MUST commitment-bind).

**Option R (user-confirmed 2026-07-04).** This is NOT an "exec-mem-only" representation. It is: **execution-units
updates with a memory-only EFFECT, proven by full `[mem, steps]` decoding and equality of the `steps` component.** That
distinction prevents accidental loss of consensus meaning — the ExUnits grammar is `array(2)[mem, steps]`
(`ledgerdb_state.rs:2010`), so a memory-only decoder would silently drop `steps`, which is forbidden.

## Probe results that fixed the design

- **`max_tx_ex_units_mem`/`_cpu` are SOURCE-BOUND** on the Conway-native path: `read_conway_pparams` decodes maxTxExUnits
  via `read_ex_units` (`ledgerdb_state.rs:1904`) into both `max_tx_ex_units_mem` + `max_tx_ex_units_cpu`;
  `mithril_native_assembly.rs:356` threads `s1a.protocol_params`; recovery reads the persisted value. `ProtocolParameters::default()`
  (14M) exists only on Mary-era/test paths. ⇒ KEEP `max_tx` in its existing bare representation — but PROVE it (gates below).
- **The pparams reserved trailing fields are Ade-internal only** (`encode_pparams` → durable snapshot + `native_protocol_params_hash`,
  never Cardano wire) — BUT Option R needs a `{mem, steps}` pair + version marker, which does not fit two slots, so we use a
  **codec arity/version bump**, NOT the reserved fields.
- **ExUnits carries `steps`**; `read_conway_pparams:1905` currently DISCARDS the block steps (`let (mem, _) = …`). S4.3b threads it.

## Piece 1 — versioned full block ExUnits state (`MaxBlockExUnits`)

```
enum MaxBlockExUnits { Unversioned, Bound { mem: u64, steps: u64 } }
```
Add `max_block_ex_units: MaxBlockExUnits` to `ProtocolParameters`. `ProtocolParameters::default()` sets it `Unversioned`.

- **Codec = a NEW pparams arity/version** (`snapshot/gov_state.rs` `encode_pparams`/`decode_pparams`), NOT the reserved
  fields: `Unversioned` encodes the CURRENT `PPARAMS_FIELDS`-arity array (BYTE-IDENTICAL to every historical store — the
  two reserved fields stay `0,0`); `Bound { mem, steps }` encodes a `PPARAMS_FIELDS + 2`-arity array (the two extra
  trailing fields = `mem`, `steps`). `decode_pparams` branches on the array header: current arity ⇒ `Unversioned`;
  `+2` arity ⇒ read the pair as `Bound`; any other arity ⇒ deterministic codec error. `Unversioned` NEVER acts as
  `{mem:0, steps:0}` or a defaulted current limit.
- **Source-binding:** `Bound { mem, steps }` may be created ONLY from the certified Conway source — thread the full
  block ExUnits from `read_conway_pparams` (change `:1905` to keep `steps`), onto the assembled `ProtocolParameters`.
- **Fingerprint** (`fingerprint.rs:440` `fingerprint_pparams`): include the FULL `{mem, steps}` pair for `Bound`
  (arity-matched); `Unversioned` fingerprints byte-identically to history.
- **Inert:** no consensus check reads `max_block_ex_units` in S4.3b.

## Piece 2 — closed full-ExUnits update decoder

Decode `ParameterChange.update` (opaque `Vec<u8>` today, OQ-2) — reading BOTH exec-units fields COMPLETELY:
`maxTxExUnits -> [mem, steps]`, `maxBlockExUnits -> [mem, steps]`. Structured closed result (no `bool`):

```
struct ExecUnitsParamUpdate {
    max_tx_ex_units: Option<ExUnits>,     // ExUnits { mem, steps }; None = key absent
    max_block_ex_units: Option<ExUnits>,
    unsupported_fields: CanonicalFieldSet, // every OTHER pparam-update key present, canonically ordered
}
```
- **Structural rejects (Malformed, at decode):** a duplicate recognized key; a recognized value that is not a
  well-formed `ExUnits array(2)`. No fallback parsing, no last-write-wins.
- **Unsupported (preserved, not dropped):** any pparam-update key other than the two exec-units keys is recorded in
  `unsupported_fields` (→ S4.3c `UnsupportedRatifiedAction`), never silently ignored.
- **Preserve original bytes** where any existing wire/hash authority needs them (the raw `update` stays available).
- **Exact keys:** the Conway `pparam_update` MAP keys for maxTxExUnits / maxBlockExUnits (from the Conway CDDL — verify
  against `ade_codec`, NOT the positional pparams-array index) — a grounding step before coding the decoder.
- **Inert:** nothing APPLIES the decoded update in S4.3b (no `apply_update` at the boundary); exercised by tests only.

The support decision is S4.3c's, but S4.3b's decoder must ENABLE it. S4.3c supports an update ONLY when: it touches no
unsupported pparam field; each supplied `steps` equals the currently-Bound `steps`; the relevant current `Bound` state
exists; all duplicate/malformed fields already rejected structurally. **A CHANGED `steps` is not malformed — it is a
valid but currently-unsupported action ⇒ `UnsupportedRatifiedAction`, zero mutation.**

## Piece 3 — V3 `PreviousPParamAction` on `ConwayGovState`

```
enum PreviousPParamAction { Unversioned, NoPreviousAction, Enacted(GovActionId) }
```
The enacted PParamUpdate root (`prevGovActionIds.pgaPParamUpdate`) is decoded today only as the census observable
`enacted_pparam_update: Option<GovActionId>` (`ledgerdb_state.rs:1318`), then dropped. Promote it.

- **`NoPreviousAction` only from an explicit source fact** — a decoded `SNothing`/null meaning "none exists" in the
  certified source — NEVER from a missing decoder field or a migration default. `Some(id) -> Enacted(id)`;
  `None (decoded SNothing) -> NoPreviousAction`.
- **Codec = V3 (11-field) gov-state extension** (`snapshot/gov_state.rs`, the existing 9=V1 / 10=V2 pattern): V3 appends
  the `prev_pparam_action` field. V1(9)/V2(10) stores decode `Unversioned` byte-identically.
- **Fingerprint** (`fingerprint.rs:492-560`): 11-field states append `prev_pparam_action`; all three variants are
  canonically distinguished; 9/10 byte-identical to history.
- **Source-binding:** thread `enacted_pparam_update` from `read_cert_state`'s `BootstrapGovImport` → the assembly →
  `ConwayGovState.prev_pparam_action`.
- **Inert:** no ratification path reads `prev_pparam_action` in S4.3b.

## Piece 4 — aggregate V11 commitment + fingerprint binding

Bump the imported-gov commitment **v10 → v11**, binding the newly-promoted authority: `prev_pparam_action` (the §5
seam requires binding on promotion from census-observable) AND the block ExUnits pair. Both the pparams fingerprint and
the gov-state fingerprint carry the full bound values, so the aggregate state fingerprint changes exactly for states
that carry the V11 fields.

## Required gates (before S4.3c)

1. **V10 stores byte-identical, decode `Unversioned`** (both `max_block_ex_units` and `prev_pparam_action`); their
   fingerprints unchanged.
2. **V11 bootstrap binds real source values** for both exec-units limits (max_tx already; max_block newly) AND the
   previous-action state.
3. **V11 encode → decode → fingerprint → persist → recover is byte-identical** (restart-equal).
4. **No constructor fabricates** `Bound{0,0}`, `NoPreviousAction` (except from a decoded SNothing), or a defaulted exec limit.
5. **Raw witness update for 69c948cd..#0 decodes deterministically** into the supported subset (both keys, full
   `[mem, steps]`, `unsupported_fields` empty).
6. **Unknown, duplicate, malformed, and mixed supported-plus-unsupported updates all have deterministic structured
   outcomes** (Malformed vs `unsupported_fields`).
7. **`max_tx` provenance proven:** a test that BOTH `max_tx_ex_units_mem` AND `max_tx_ex_units_cpu` (steps) are present
   in authoritative Conway state and survive persist/recover; + a regression proving NO Conway-native bootstrap
   constructor reaches `ProtocolParameters::default()`.
8. **S4.3a boundary behaviour stays INERT:** no enactment, no pparam/root mutation, same terminals; CE-3d / S4.3a gates
   unchanged (old states fingerprint identically).

## Slice boundary

ONE BLUE code slice — **S4.3b — V11 executable execution-memory and previous-action state**: versioned full block
ExUnits state + closed full-ExUnits update decoder + V3 `PreviousPParamAction` + aggregate V11 commitment/fingerprint
binding. Splitting would create intermediate schemas that still cannot safely enact the witness.

Then a SEPARATE operational capstone — **S4.3b-bootstrap — new V11 Mithril re-bootstrap + warm-restart evidence** —
before S4.3c. S4.3c must NOT manufacture its own V11 store on first use (that would blur source-lineage proof with
consumption proof).

## What S4.3b does NOT do (→ S4.3c)

No enactment: nothing applies the decoded update, advances `prev_pparam_action`, or checks a proposal's `prev_action`
against the root. Those are S4.3c's atomic exec-units enactment (full RATIFY incl. lineage + steps-equality;
`UnsupportedRatifiedAction` for out-of-subset / changed-steps updates).
